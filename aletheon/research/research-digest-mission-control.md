## TOPIC: claude-embed

### RECOMMENDATION
For Aletheon, use a two-stage architecture. STAGE 1 (build this week, near-zero code): make the central Claude panel a ttyd iframe running the real interactive Claude Code TUI inside tmux — `ttyd -W -i 127.0.0.1 -O -c leo:<secret> -t disableLeaveAlert=true -t 'theme={...}' tmux new -A -s claude claude` — using the prebuilt ttyd 1.7.7 binary (or build main with apt-installed cmake for the 2026 fixes). This gives streaming, permission prompts, Shift+Tab modes, and session persistence for free, styled to the dashboard via -t/URL-query xterm.js options. The surrounding Mission Control shell should be a single never-reloading page of iframes (Glance/Beszel, Immich, sim viewport, video studio, recruiter panel), each non-Claude panel listening to a tiny SSE endpoint; a PostToolUse hook (matcher Edit|Write, async:true, filtered to ~/dash/config/) plus a belt-and-braces inotifywait watcher POSTs reload events, so Claude editing config files hot-reloads the panels around the static Claude iframe — exactly the 'Claude panel stays static, everything else live-morphs' design the user proposed, and it sidesteps the iframe-remount problem. Run the panel session in auto or acceptEdits mode, never --dangerously-skip-permissions (Anthropic reserves bypass for isolated containers/VMs; the TUI prompts render right in the dash). Keep everything on 127.0.0.1 since the kiosk Chrome is local; bind the Tailscale interface only if phone access is wanted, or add Happy (slopus/happy, MIT, thriving) as the phone companion. For dashboard buttons that trigger scoped actions, shell out to `claude -p --output-format stream-json --resume <pinned-session-id> --permission-mode dontAsk --allowedTools ...`. STAGE 2 (when the terminal aesthetic stops being enough): replace the ttyd panel with a custom chat panel on @anthropic-ai/claude-agent-sdk 0.3.x (currently 0.3.296, pointed at the host's native claude via pathToClaudeCodeExecutable, settingSources ['user','project'] so hooks still fire) using streaming-input mode + canUseTool to render permission requests as dashboard buttons — budget a few hundred lines for the WebSocket bridge since no official web-UI example exists. Avoid building on sugyan/claude-code-webui (archived 5/2026), Crystal (deprecated 2/2026), sshx (no self-hosting), and Conductor (Mac-only); siteboon/claudecodeui (active, 14k stars, AGPL) is worth installing as a separate full-screen tab for mobile/couch use, not as the embedded panel.

## TOPIC: sim-env

### RECOMMENDATION
Build the physics panel on Newton + Rerun, with Genesis as the second engine for soft-matter spectacle, and skip Taichi and (by default) Isaac Sim. Concretely for the Aletheon box: (1) Primary engine: Newton (pip install "newton[examples]", v1.6.1/1.7.x) in a dedicated conda env — it is the official successor to warp.sim, Linux Foundation-governed (Disney/DeepMind/NVIDIA), rides Warp 1.18 whose CUDA 13.4 wheels explicitly require exactly the R580+ driver and support sm_75+ (the 580.178 / sm_120 / CUDA 13 combo on this machine is the blessed path), wraps MuJoCo Warp for rigid bodies plus cloth/softbody/MPM solvers, and — decisively — has a built-in `--viewer rerun` that streams straight into the dashboard. (2) Visualization: rerun-sdk 0.38.x; the sim process calls rr.serve_grpc(), and the Mission Control dashboard embeds the viewer as an iframe panel (https://app.rerun.io/version/{installed_ver}/index.html?url=rerun+http://localhost:<port>/proxy&theme=dark, or self-hosted via @rerun-io/web-viewer-react for fully offline operation); one rerun blueprint gives the 3D viewport, live time-series plots, and text-log stream the user asked for — generate the iframe URL from the installed SDK version because viewer/SDK versions must match exactly. (3) Secondary engine: genesis-world (active through Sep 2026; Blackwell supported via its gstaichi fork since Nov 2025, but watch for Ada/Blackwell solver-hang regressions) for MPM/SPH/FEM/IPC "sand, water, cloth, jelly" prompts; log its frames into the same rerun viewer. (4) Prompt->sim architecture: don't let Claude free-write engine code (2026 benchmarks: ~21.5% pass rate); keep a repo of vetted Newton/Genesis scene templates with a YAML/JSON parameter schema that Claude edits, a 10-step GPU dry-run validator, and a log-feedback repair loop — this is also exactly the "Claude edits config files, panels hot-reload" model of the whole dashboard. (5) GPU hygiene: launch every sim with CUDA_VISIBLE_DEVICES=GPU-<uuid-of-GPU1> (UUIDs from nvidia-smi -L; immune to device-ordering surprises with two identical 5090s) while GPU0 drives the three Wayland displays; the dashboard's GPU widget polls NVML (nvidia-ml-py) for GPU1 device utilization plus the compute-PID list, treating per-PID SM% from nvidia-smi pmon as indicative only. (6) Skip: Taichi upstream (last release Jul 2025, RTX 5090 bugs open and unanswered — any legacy demo gets ported to Warp/Genesis); Isaac Sim 6.1 only as an optional Docker container later (Apache 2.0 and 5090-capable, but Ubuntu 26.04 is unsupported, source builds reject gcc 13, and it is far heavier than needed for prompt-driven personal sims); MJX/JAX (jax[cuda13]) only if JAX-based RL training becomes a goal, since Newton already provides MuJoCo-Warp physics.

## TOPIC: video-studio

### RECOMMENDATION
For the Aletheon workstation, build the video studio in two layers. LAYER 1 (install now, zero cost, fully Claude-scriptable): Kdenlive 26.08.2+ as the GUI editor — native package (KDE backports/PPA, NOT Flatpak, which breaks NVENC via sandboxed libcuda), Qt6 Wayland-native so it behaves on Plasma 6.6 Wayland, decodes all 3,784 iPhone HEVC/AAC clips out of the box, has built-in Whisper subtitles and NVENC 10-bit HEVC render profiles, and — decisively for Mission Control — stores projects as MLT XML that Claude Code can generate/edit as text and render headlessly with melt (MLT 7.40). Pair it with the programmatic toolchain Claude will actually use for 'cut me a highlight reel': Ubuntu's ffmpeg 8.0.1 with av1_nvenc/hevc_nvenc on the 5090s (-preset p7 -tune hq, split batches across -gpu 0/1), WhisperX (conda, sm_120 PyTorch) for word-level transcript-driven cuts, and auto-editor for silence-based rough cuts exported straight into Kdenlive project files. Put proxies/render cache on the empty 'scratch' NVMe pool and keep the ZFS library read-only; tone-map iPhone Dolby Vision P8.4 (plain HLG base layer) to SDR with the zscale+tonemap=hable:desat=0 or libplacebo bt.2390 recipes when delivering. Add ComfyUI with SeedVR2 (restoration/upscale — 32GB VRAM comfortably runs the 7B model) and ComfyUI-Frame-Interpolation (RIFE 4.26/FILM) for AI enhancement of both iPhone and AI-generated clips. LAYER 2 (optional ~$295 upgrade, decide after Layer 1 is in use): DaVinci Resolve STUDIO 21.1 — NOT the free version, which on Linux cannot read H.264/HEVC/AAC at all and lost Python scripting entirely in 21.1. Studio is worth it specifically because 21.1 added a native MCP server officially supporting Claude Code (File > Setup AI Assistants), giving the Mission Control chat panel first-party agentic control of a pro NLE, plus dual-5090 processing and proper Rec.2100-HLG color management for the iPhone footage. Accept its frictions: AAC audio still needs an ffmpeg pre-transcode, Ubuntu 26.04 install needs the bundled-glib removal workaround (unsupported distro), and it runs under XWayland. For the dashboard's video panel, surface render-queue status from melt/ffmpeg job logs and let Claude edit Kdenlive XML + ffmpeg job specs as the hot-reloadable config files.

## TOPIC: master-shell

### RECOMMENDATION
Build the Mission Control as ONE master page in a single Chrome kiosk window pinned to DP-2, not as KWin-tiled windows. Concretely for Aletheon: (1) GATEWAY — docker-compose Caddy as a single-origin gateway at http://localhost:8080 (optionally aliased dash.local in /etc/hosts). (2) SHELL — option (c)(1): a static HTML/CSS-grid/vanilla-JS page (zero build step, instantly hot-editable by Claude) with a ttyd iframe (`ttyd -W -b /claude ... tmux new -A -s claude claude`) as the static central panel; persona = one CSS-custom-properties theme file + a layout.json; add vendored gridstack.js later only if drag-rearranging is wanted. (3) LIVE RELOAD — a ~40-line Node watcher (chokidar v4) exposing an SSE endpoint through Caddy; Claude edits config/theme files on disk, the watcher emits `{panel, action}`, the shell reloads only the affected iframe — critical because Glance hot-reloads its YAML server-side but never pushes a browser refresh.
